# Voice Input Engine Preference

## Summary

语音输入新增引擎优先级设置：用户在 系统语音（SFSpeech）、SenseVoice、FunASR-Nano 之间指定优先使用哪一个，默认系统语音。选中的引擎可用时按用户的选择执行，不可用时按本文件的降级规则处理，不再由硬编码的自动优先级决定。

---

## Problem Frame

语音输入的引擎选择完全自动：只要 SFSpeech 已授权且当前语言被支持就走系统语音，只有这两个条件不满足时才降级到本地模型；本地模型用哪个也是硬编码的（优先 FunASR-Nano，其次 SenseVoice），与用户在转写页选择的模型无关。

这套自动策略隐含了「系统语音体验最好」的假设，但系统语音默认走 Apple 服务器识别：需要联网、音频外发，对专有名词和中英混说也容易出错。用户在意的东西并不一致——有人要最接近零延迟的响应，有人要音频不出本机，有人要特定模型的中文或术语表现——而现在没有任何表达入口。想用本地模型的用户只能通过把识别语言改成一个系统语音不支持的语言来触发降级。

---

## Actors

- A1. 用户：在设置里指定优先引擎，按住触发键说话。
- A2. VoiceGum App：读取偏好、选择引擎、驱动语音输入会话。
- A3. 引擎：系统语音、SenseVoice、FunASR-Nano 三者，各有自己的可用前提（授权、网络与语言支持、模型是否已下载）。

---

## Key Flows

- F1. 指定优先引擎
  - **Trigger:** 用户在 设置 → 通用 → 语音输入 中选择一个引擎
  - **Actors:** A1, A2
  - **Steps:** 打开设置 → 选择引擎 → 偏好持久化
  - **Outcome:** 之后的语音输入会话以该引擎为首选
  - **Covered by:** R1, R2, R3, R4

- F2. 首选引擎可用时的语音输入
  - **Trigger:** 用户按住触发键，首选引擎满足可用前提
  - **Actors:** A1, A2, A3
  - **Steps:** 录音 → 首选引擎识别 → 文本注入
  - **Outcome:** 注入的文本来自用户指定的引擎
  - **Covered by:** R5

- F3. 首选引擎不可用
  - **Trigger:** 用户按住触发键，但首选引擎不满足可用前提
  - **Actors:** A1, A2
  - **Steps:** 首选为系统语音（未授权 / 语言不支持 / 识别不可用）→ 静默降级到已下载的本地模型 → 正常注入；首选为本地模型但该模型未下载 → 提示前往设置下载 → 结束本次会话
  - **Outcome:** 用户要么拿到文字，要么明确知道为什么没拿到
  - **Covered by:** R6, R7

---

## Requirements

**设置项**
- R1. 设置 → 通用 → 语音输入 中新增「优先引擎」选择，选项为 系统语音、SenseVoice、FunASR-Nano，默认 系统语音
- R2. 该项仅在「语音输入」开关打开时可见，与触发键设置同级
- R3. 选择结果持久化，重启应用后保持
- R4. 该设置只作用于语音输入，不影响文件转写页的引擎与模型选择

**引擎选择与降级**
- R5. 首选引擎可用时，语音输入会话必须使用该引擎，不再被自动优先级覆盖
- R6. 首选为系统语音但不可用时，静默降级到已下载的本地模型，不弹错误提示
- R7. 首选为本地模型但该模型未下载时，提示用户前往设置下载并结束本次会话，不得静默改用系统语音或另一个本地模型
- R8. 首选为本地模型且模型已下载时，语音输入按用户指定的模型运行，不再按固定顺序挑选本地模型

**可观察性**
- R9. 悬浮窗继续以现有配色区分「系统语音」与「本地模型」，使用户能察觉发生了降级

## Acceptance Examples

- AE1. **Covers R1, R5.** 用户把优先引擎设为 SenseVoice 且模型已下载，按住触发键说中文，松开后注入的文本由 SenseVoice 产出，全程不走系统语音。
- AE2. **Covers R3.** 用户把优先引擎设为 FunASR-Nano，退出并重启应用后设置仍为 FunASR-Nano。
- AE3. **Covers R6.** 优先引擎为系统语音，语音识别权限被拒或当前语言不被系统语音支持，且至少有一个本地模型已下载：用户按住触发键说完松开，会话静默降级到本地模型，文本正常注入。
- AE4. **Covers R7.** 优先引擎设为 FunASR-Nano 但该模型未下载：用户按住触发键说话，悬浮窗提示前往设置下载，不注入文本，音频不发送到 Apple 服务器。
- AE5. **Covers R4.** 优先引擎设为 SenseVoice，文件转写页选择在线 API：文件转写仍走在线 API，语音输入走 SenseVoice。

---

## Success Criteria

- 用户能在设置里直接看到并切换语音输入使用的引擎，不再需要靠改写识别语言来绕开系统语音
- 首选引擎可用时，实际运行的引擎与设置一致，且用户能从悬浮窗验证
- 引擎不可用时的行为可预期：不会在未告知的情况下把音频发给 Apple，也不会在未告知的情况下换用别的模型
- 默认值与升级前行为一致，现有用户升级后无感知

---

## Scope Boundaries

- 不统一语音输入与文件转写的模型设置
- 不做本地模型预热或常驻：本地引擎仍按需加载，多出来的等待时间由用户的选择承担
- 不做按语言或内容自动选择引擎的路由逻辑
- 不把在线 ASR（Whisper / 火山引擎）引入语音输入
- 不改变系统语音是否使用设备端识别的行为，不引入强制 on-device 开关

---

## Key Decisions

- **三选一而非两选一（系统语音 vs 本地）**：本地两个模型的代价差异很大——SenseVoice 加载 0.17s、RTF 0.01，而 FunASR-Nano 走 LLM 自回归解码（见 `docs/brainstorms/2026-05-14-asr-performance-benchmark-results.md`）。合并成一个「本地」选项会让用户失去真正想控制的那一层。
- **默认系统语音**：保持升级前行为；本地路径没有流式文本，还要求用户先下载模型。
- **首选不可用时不做静默替换**：用户显式选择本地引擎，背后往往是「音频不出本机」的意图，静默回退到系统语音会直接违背它。
- **本文件取代 `docs/brainstorms/2026-06-29-hold-to-talk-voice-input-requirements.md` 中 R5/R6/R7 的引擎优先级部分**，该文档其余内容不变。

---

## Dependencies / Assumptions

- 复用现有的降级与错误路径：语音识别授权与语言支持判定、模型未下载提示、悬浮窗引擎配色。
- 本文件不量化 SenseVoice 与 FunASR-Nano 的识别质量差异；「SenseVoice 排在 nano 之前」是排序建议，不是准确度结论。
- 系统语音的可用性判定沿用现状（授权 + 语言支持），不新增网络探测。
